# Coding Rules & Conventions — My Quick Trippers

## 1. Folder Structure Rules

```
src/app/          ← Routing only. Pages call components; minimal inline logic.
src/components/   ← Reusable UI. Subfolders: layout/, ui/, forms/, package/
src/data/         ← Static data only. No business logic here.
src/lib/          ← Pure utility functions (cn, slugify). No React imports.
src/utils/        ← Reserved. Currently empty.
scripts/          ← One-off Node.js/TS data pipeline scripts. NOT imported by Next.js.
public/           ← Static assets. Never import these in JS — reference via /path.
```

**Rules:**
- Never put page logic directly in route files — extract into components.
- Never import from `scripts/` in `src/` code.
- Never edit `allPackages.ts` by hand — it is generated by `scripts/transform-scraped-packages.ts`.
- Never edit `scraped_data/` by hand — it is scraper output.
- `src/data/siteConfig.ts` is the **single source of truth** for all brand/contact data. Never hardcode phone numbers, emails, domain, or social links elsewhere.

## 2. Naming Conventions

### Files
| Type | Convention | Example |
|---|---|---|
| React components | PascalCase `.tsx` | `PackageCard.tsx` |
| Data files (TS) | camelCase `.ts` | `navLinks.ts`, `siteConfig.ts` |
| Data files (JSON) | camelCase `.json` | `packageDetails.json` |
| Script files | kebab-case `.js/.ts` | `copy-scraped-images.js` |
| CSS custom classes | kebab-case with prefix | `.pm-card`, `.poster-lb-backdrop`, `.nit-ribbon` |
| Route segments | kebab-case (Next.js App Router) | `special-tours/`, `customer-center/` |
| Dynamic segments | `[slug]` | `packages/[slug]/page.tsx` |

### Variables & Types
- TypeScript `interface` for component props and data shapes (not `type` for objects)
- `PascalCase` for interfaces: `PackageCardProps`, `PosterItem`, `SiteConfig`
- `camelCase` for all variables and functions
- `SCREAMING_SNAKE_CASE` for top-level page constants: `TRENDING_PACKAGES`, `NORTH_PACKAGES`
- `as const` on config objects: `export const siteConfig = { ... } as const`

## 3. TypeScript

- **Strict mode** is expected (verify in `tsconfig.json`).
- Path alias `@/` maps to `src/` — always use `@/` imports, never relative paths from deep directories.
- Avoid `any` — use `unknown` with type narrowing, or define proper interfaces.
- JSON imports: cast with `as Record<string, any>` only when the JSON schema is truly dynamic (see `sitemap.ts`).
- Component prop types defined inline with the component via `interface` (not in separate `.types.ts` files unless shared across 3+ components).

## 4. Linting & Formatting

**ESLint config:** `eslint-config-next` (next/core-web-vitals + next/typescript)

Enabled rule sets:
- `next/core-web-vitals` — CWV-related rules (no `<img>` without `next/image`, etc.)
- `next/typescript` — TypeScript best practices

**What this means in practice:**
- Always use `next/image` (`<Image>`) instead of raw `<img>` for any image that Next.js should optimise. Exception: the Navbar logo uses raw `<img>` — this should be fixed.
- Always provide `alt` text on images.
- No unused variables (TS rule).
- Prefer `const` over `let`.

**No Prettier config found.** Formatting is editor-dependent. Recommended: 2-space indent, single quotes, no semicolons (match existing code style).

## 5. CSS / Styling

**Tailwind CSS v4** via `@import "tailwindcss"` in `globals.css`.

- Define all design tokens in the `@theme {}` block in `globals.css` (not in `tailwind.config.js` — v4 doesn't use one by default).
- Use `@layer utilities {}` for custom utility classes.
- Write component-specific CSS (marquee, lightbox) directly in `globals.css` using plain CSS class names (`.pm-card`, `.poster-lb-backdrop`).
- **CSS class naming for custom blocks:** use a short prefix to avoid collision:
  - `.pm-*` — poster marquee
  - `.poster-lb-*` — poster lightbox
  - `.nit-*` — legacy NamasteIndia-style ribbon
- Never use `@apply` with Tailwind v4 utilities in custom CSS — use native CSS properties.
- Never use inline `style={{}}` for layout — use Tailwind classes or custom CSS classes. Exception: dynamic values that cannot be expressed statically (animation duration, transform).

## 6. Component Patterns

- **"use client"** directive: add only when the component uses React hooks, event handlers, or browser APIs. Server Components are the default.
- Import order: external libraries → Next.js → internal `@/components` → internal `@/data` → types
- Keep components focused — if a component exceeds ~150 lines, extract sub-components.
- Prefer named exports for utility functions; default exports for React components (Next.js page convention).
- The `cn()` utility from `@/lib/utils` should be used for all conditional className merging.

---

## 7. Data Handling

- `allPackages.ts` must be regenerated (not hand-edited) whenever package data changes.
- `packageDetails.json` contains 121 rich itinerary objects — this is the authoritative source for package detail pages.
- `redirects.json` is loaded in `next.config.ts` — any edits must produce valid JSON or the build will fail entirely.
- `fullBlogData.json` is 13.5 MB — avoid importing the whole file in client components. Only import in Server Components or API routes.

---

## 8. Things NOT To Do

- ❌ Do not hardcode phone numbers, emails, or social URLs — use `siteConfig`.
- ❌ Do not use `<img>` for content images — use Next.js `<Image>`.
- ❌ Do not use `hover: scale()` CSS transforms on elements inside `overflow: hidden` containers — causes clipping. Use glow/border effects instead.
- ❌ Do not `import` from `scripts/` in any `src/` file.
- ❌ Do not commit `packageDetails.json.backup` — add to `.gitignore`.
- ❌ Do not add `z-index` values less than 9999 to lightboxes/modals — the Navbar has `z-[1000]`.
- ❌ Do not add new packages to `allPackages.ts` manually — run the transform script.
- ❌ Do not add redirects directly to `next.config.ts` — add them to `redirects.json`.
- ❌ Do not add `overflow: hidden` to the hero section — it will clip the poster marquee.
- ❌ Do not use Tailwind `!important` utilities — fix specificity properly.
- ❌ Do not put large JSON files in `src/data/` without confirming they are tree-shaken (only use what you need from them).
